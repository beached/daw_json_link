Strings

JSON natively encodes strings. There are two options for mapping them to C++ data structures, fully processed and raw strings. Raw strings only find the end of the string and do not change the underlying values.

Escaped

{
"uris": [
"example.com",
"B\u00FCcher.ch",
"happy.cn",
"happy\u5FEB\u4E50.cn",
"\u5FEB\u4E50.cn",
"happy.\u4E2D\u56FD",
"\u5FEB\u4E50.\u4E2D\u56FD",
"www.\u30CF\u30F3\u30C9\u30DC\u30FC\u30EB\u30B5\u30E0\u30BA.com",
"\uD83E\uDD84.com"
]
}

The above JSON document consists of an array member named "uris" with an element type of string.

The C++ std::vector<std::string> of the above json should be equivalent to:

++
std::vector<string> uris = {
"example.com",
"Bücher.ch",
"happy.cn",
"happy快乐.cn",
"快乐.cn",
"happy.中国",
"快乐.中国",
"www.ハンドボールサムズ.com",
"🦄.com"};

To see a working example using this code, refer to cookbook_escaped_strings1_test.cpp.

Below the mapping of the JSON object with C++ data structures.

++
struct WebData {
std::vector<std::string> uris;
};
namespace daw::json {
template<>
struct json_data_contract<WebData> {
using type = json_member_list<
json_array<"uris", std::string>
>;
static inline auto
to_json_data( WebData const &value ) {
return std::forward_as_tuple( value.uris );
}
};
}

Trusted, already-escaped strings

By default, json_string validates UTF-8 and escapes the value during serialization. When an application can guarantee that a value is valid UTF-8 and is already escaped as JSON string content, the EscapeValidUTF8::AssumeValid mapping option writes those bytes directly:

++
struct WebData {
std::string escaped_uri;
};
namespace daw::json {
template<>
struct json_data_contract<WebData> {
using type = json_member_list<
json_string<
"escaped_uri",
std::string,
options::string_opt( options::EscapeValidUTF8::AssumeValid )>
>;
static inline auto to_json_data( WebData const &value ) {
return std::forward_as_tuple( value.escaped_uri );
}
};
}

For example, a value containing the bytes already escaped: \"quoted\\"</tt> is safe for this mapping because its quotation marks already have JSON escape characters. A value containing unescaped quotation marks is not safe and can produce invalid JSON. This option affects serialization only. <tt>from_json</tt> continues to decode and unescape a <tt>json_string</tt> normally. Consequently, a value produced by parsing must not automatically be treated as suitable for <tt>AssumeValid</tt>; the application must establish that it is already escaped before serializing it. Character pointers are only converted when passed directly. Inside a container they are deduced as a nullable char, so to_json( ptrs ) writes the first character's code.

Containers of character pointers

To write a container of character pointers as strings, map the element explicitly as a nullable string. A nullptr element is written as null.

++
using char_ptr_string = daw::json::json_nullable_no_name<
char const *, daw::json::json_string_no_name<daw::string_view>>;
using char_ptr_strings = daw::json::json_array_no_name<char_ptr_string>;
std::vector<char const *> ptrs{ "A\"da", nullptr };

The same element mapping works as a member of a json_data_contract. The container type must be given, as it is not the default for the element type:

++
struct Names {
std::vector<char const *> names;
};
namespace daw::json {
template<>
struct json_data_contract<Names> {
static constexpr char const names[] = "names";
using type = json_member_list<
json_array<names, char_ptr_string, std::vector<char const *>>>;
static constexpr auto to_json_data( Names const &value ) {
return std::forward_as_tuple( value.names );
}
};
}

to_json( Names{ ptrs } ) writes {"names":["A\"da",null]}. This mapping is serialization only: from_json<Names> does not compile, as a char const * cannot be constructed from a parsed string.

Alternatively, use a container of std::string_view or write the elements with json_writer::write_array_values.

Already escaped values

Passing an explicit raw mapping writes the value as-is. The value must already be valid, escaped JSON string content.

++
using raw = json_string_raw_no_name<daw::string_view>;

Expression Output
to_json<raw>( R"(A\"da)"sv ) "A\"da"
to_json<raw>( R"(A\"da)" ) "A\"da"

A std::string_view member of a json_data_contract is also raw. Given a contract mapping json_link<"value", std::string_view> for Member, to_json( Member{ R"(A\"da)" } ) writes {"value":"A\"da"}. Likewise a char member of a contract, json_link<"c", char>, remains a number: ‘to_json( CharMember{ 'z’ } )writes{"c":122}`.

Invalid UTF-8

With the default RestrictedStringOutput::ErrorInvalidUTF8 output option, valid UTF-8 is written unchanged and invalid UTF-8 is an error.

Expression Output
to_json( "caf\xC3\xA9"sv ) "café"
to_json( "\xC3"sv ) throws json_exception with ErrorReason::InvalidUTFCodepoint

A lone byte above 0x7F is not a complete UTF-8 character, so to_json( char( 0xC3 ) ) also throws.
